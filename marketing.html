Self-hosted multiplayer persistence / NeoForge 1.21.1 / early prototype

The world stays up. The host can change.

mcmesh keeps a Minecraft world on a small gateway and lets whichever player is online and strongest host it from their own machine. When they log off, the next player takes over from the last save. Players never touch port forwarding, and nobody has to leave a PC running overnight.

The problem

A friend-group server dies the night its owner goes to bed.

Someone hosts from their own PC, so the world exists only while that PC is on. Someone else rents a VPS, so one person pays every month and everyone else asks permission. A third person tries port forwarding and discovers their ISP put them behind CGNAT.

mcmesh treats the world as the durable thing and the machine as replaceable. The world lives in a content-addressed store on a gateway you run. Hosting becomes a turn that passes from player to player, not a job one person owns.

What happens when the host leaves

Five steps, all automatic.

  1. SyncBefore hosting, the mod pulls the newest revision from the gateway. If it already holds an older copy it fetches only the changed chunks, and it falls back to a full download if anything does not match.
  2. LeaseThe gateway grants one host at a time, with an epoch number that makes a stale host harmless. Election weighs a measured hardware score, and a challenger must be clearly stronger (a 1.3x margin) before it may take over a running world.
  3. PlayGuests connect to the gateway address. A ticket gate checks each login, and the relay forwards traffic to the current host over a tunnel the host opened outward. Voice chat UDP rides the same relay.
  4. SaveChanged chunks stream to the gateway as the host plays. Every revision is hash-chained, commits are signed with the host's device key, and a sanity gate refuses a commit that would wipe most of a world.
  5. Hand overThe host commits a final revision, the gateway elects the next one, and guests reconnect to the same address behind a "switching host" screen instead of a disconnect error. Players are reconnected, not teleported across; seamless transfer is still research.

What is inside

Built around not losing the world.

Data safety

Every autosave is a revision. Restoring one from the web panel adds a new save on top, so a restore can be undone and nothing is deleted. Scheduled scrub and incremental backup, crash recovery to the last intact revision, and a world zip export keep you from being locked in.

A world over its storage quota pauses uploads. It never deletes anything, and existing revisions stay downloadable.

Hosting

Hardware-ranked election, load shedding that lowers view and simulation distance while TPS is low, battery-aware handover for Linux laptops, and an optional vote when players want to move the world themselves.

An anchor node, a small always-on machine, can sit in standby and take the world when no desktop is online, then yield when a capable player returns.

Operating

Per-user and per-world quotas, an append-only audit log, suspend and ban, maintenance mode, Prometheus metrics, a public status page, signed webhooks, scoped API keys, rate limits and expiring invite links. Admins get a usage page in the panel.

Modpacks

Per-pack signed auto-update with a pinned author key and an opt-out, a per-pack allowlist that keeps an incompatible host from taking the world, and a memory pre-check before hosting or joining.

Trust

Ed25519-signed commits, a hash chain over every revision, and self-hosting parity: the gateway binary has every feature, limits are quotas you set, and nothing is compiled in as a cap.

Who it is for

Groups that outlive any one computer.

Good fit

  • Friend groups on a shared modpack who play at different hours.
  • Self-hosters with a spare box or a cheap VPS who want the world safe and the load shared.
  • Communities that want a server with no single owner and no single point of failure.
  • Modpack authors who want players to stay on the exact pack, updated and signed.

Not for you yet

  • Anyone who needs vanilla or Bedrock clients with no mod. The mod is required.
  • Loaders and versions other than NeoForge 1.21.1. A second target is planned, not built.
  • Players who want a hosted service. Today you run the gateway yourself.

Honest status

Seamless handover

From a reconnect screen to no screen at all.

Today a handover reconnects players behind a "switching host" screen. The plan is to shrink that gap in three steps, and to measure each before promising it. The vision figure for the last step comes from our own design notes and is not yet measured.

Now

Reconnect behind a screen

The final commit lands, the next host boots, guests reconnect to the same address. Nothing is lost; players see a pause.

Next

Shadow pre-boot and transfer packet

The incoming host hydrates in the background while the old one keeps ticking. On 1.20.5 and newer, the transfer packet moves guests without a manual reconnect, with the screen as the fallback below that.

Research

Ghost standby

A guest's already loaded client registries start the server on takeover. The design notes aim for under 1.5 seconds; that number is a target until it is measured.

Bar length is relative pause time as designed, not a benchmark.

Shared compute

Idle machines are a resource. Use them without risking the world.

A mesh has more than one computer in it. Most of the time only one is working hard. The research track asks how much of the rest can help, under one rule that does not bend: the server loop stays vanilla-shaped on a single host, and mod block entities never tick out of step across machines.

Distributed world generation

Terrain a player is about to reach is generated ahead of them on other machines. The world is cut into macro-tiles of 8x8 or 16x16 chunks with a halo for structures and features, and tiles are leased by arrival time: urgent ones on the host, the near horizon on strong desktops, the far horizon on laptops or the anchor. Workers run at minimum priority and stand down when free heap falls under 25% or frames under 45 per second.

Open question: whether results stay identical to the host's own generation across seeds and mod worldgen. Nothing ships until that is proven.

Sub-tick offload

Read-only work such as pathfinding, lighting and mob sensing is computed by a peer, which returns intents. The host thread applies them in order, so the world remains deterministic on one machine.

Needs a measured case first. If transport costs more than the work, it does not ship.

Sharding by islands

Groups of active players, forced chunks and linked contraptions become islands with a 3-chunk safety halo. Each island could be ticked on its own host. A write outside the owned set is trapped, and when a mod couples two islands they merge back automatically.

The largest item on the list. Everything in the mod API about coupling and affinity exists to feed it, and none of that ships before this is proven.

For developers

Five ways in, from a JSON file to a sandboxed plugin.

Most mods need nothing. Some need a few lines of declaration. A handful need real code. The platform is staged so each step is useful alone, and each deeper step costs more review before it can run.

Compat manifest
planned

A JSON file inside your mod jar says which files to sync and with what scope, which UDP ports to relay, which blocks need pinning, and which entities must never be removed. No code, no dependency.

Gateway API plane
partly built

Scoped API keys, an event long poll, signed webhooks, read access to revisions, manifests and blobs, and Prometheus metrics. Write a bot in any language and run it as a sidecar. Discord status, map rendering and offsite backup are meant to live here, outside the gateway process.

Java mod API
planned

A small MIT-licensed library. Ask whether the world is hosted here or by a peer, listen for pre-migrate and post-promote events, store data that follows the world, and hand a snapshot of your state to the next host. Every call turns into a no-op when mcmesh is absent, so your mod still runs on a plain server.

Panel widgets
planned

Declare a toggle, slider, gauge or action button as JSON and it shows up in the web panel and the in-game settings screen. For more, mount a Web Component in a named slot with the panel's theme tokens.

Gateway plugins
security review first

Custom storage backends, auth providers, relay stages and election hooks, running as sandboxed Wasm with capability-gated imports and CPU limits. Native plugins stay off unless an operator allowlists an exact hash. Only built if the sidecar plane turns out not to cover the demand.

Ecosystem

The rest of the picture.

Runs anywhere

One static Rust binary, multi-arch images, and templates for CasaOS, Umbrel, Runtipi, Unraid, TrueNAS SCALE, Coolify, Dokploy, Portainer, a Pterodactyl or Pelican egg and a NixOS module. A hardened systemd unit and container example exist today.

Later: an optional permanent address for a gateway behind CGNAT through an outbound tunnel, and an Android gateway app for a phone in a drawer.

More versions

NeoForge 1.21.1 today. Next, a loader-independent core so 1.20.1 on Forge and Fabric can follow, with Java 21 features moved behind an abstraction first. Older versions are out of scope, with a sidecar-based research path for 1.7.10-class packs.

Easier joining

Invite links that open a landing page and redeem from the clipboard are built. Planned: an mcmesh:// link scheme, Prism and Modrinth App launch integration, and a one-click Share World that converts a singleplayer save, uploads it and copies the invite.

Community tools

Region rollback exists. Planned: a block log, rollback by player or time window that spares claims, ownership transfer, ban sync, reports, world templates and forks, read-only demos, an offline join queue, friends and presence, a public directory with tags, and a Polish-first localization.

Outside the process

Sidecar workers on the API plane: a Discord bot with a live status embed, an async BlueMap or Squaremap renderer fed from the store with zero load on the host, offsite backup to S3, Backblaze B2 or rclone, wake-on-LAN and Home Assistant triggers for an idle world, and a Grafana dashboard.

Safer worlds

Tick quarantine, which serializes and removes a block entity or entity that throws or runs away, instead of crashing the host, never silently and with a never-delete list. A rolling local mirror so every player holds a singleplayer-ready copy. A profiler trigger when ticks stay slow.

Between servers

Federation research: signed transfer tickets that let a player cross between gateways through portals, and a world directory built on the meta-server work already shipped.

Bedrock

A planned crossplay path through Geyser and Floodgate for worlds that stay vanilla-wire, with Bedrock players fixed to the client-only role and held through a handover on a loading screen.

Hosted plans

A paid service is optional, and it is last.

Self-hosting parity is a standing rule: the binary you can download has every feature any hosted offering has. Limits are quotas an operator sets, never caps compiled in.

  • Hosted gateways with plans for storage, worlds, retention and relay bandwidth. A lapsed plan pauses uploads and never deletes a world.
  • Pay-as-you-go anchors: prepaid credits billed per active minute by memory profile, never expiring, with the clock stopping the moment the anchor hands back to a player.
  • A public cost page showing monthly infrastructure and bandwidth cost next to revenue.
  • A creator program: managed gateways scoped to a modpack with signed auto-update and a crash dashboard, and a revenue share on what a creator's pack brings in.
  • Regional gateways with latency-based selection.

Gated on a free closed beta that measures real storage and bandwidth per world, and on legal review: Mojang commercial guidelines, mod redistribution licenses, GDPR, taxes and terms. Nothing here is on sale.

Hard limits

What this project will not do.

These are the promises that make everything above safe to want.

Never

  • Ship a change that can lose player data. When unsure, a test comes first.
  • Delete a world because a quota ran out. Uploads pause; saves stay downloadable and playable.
  • Tick mod block entities out of step across machines, or replace the server loop.
  • Download or run code on a player's machine without a pinned author key, a prompt and an opt-out.
  • Run native plugins inside the gateway by default.

Rejected, with reasons

  • Bytecode rewriting of hot vanilla loops: it collides with other mods' mixins and breaks on every game update.
  • Slowing background ticks with a progress multiplier: it changes behaviour mods can see.
  • Client-side physics guesses: desync and a cheating surface without a measured need.
  • Lock-in. The zip export, the backup command and the local mirror stay first-class.
